01 — PROJECT OVERVIEW

NeuroScan AI: Multiclass Brain Tumor Classification

NeuroScan AI tackles one of the most clinically critical tasks in neuro-oncology: rapid, accurate classification of brain MRI scans into four diagnostic categories — Glioma, Meningioma, Pituitary Tumor, and No Tumor. Each class presents distinct morphological signatures in MRI that a deep learning model can learn to discriminate with high precision when trained appropriately.

The system is built around EfficientNetB0, a compound-scaled convolutional neural network pre-trained on ImageNet, fine-tuned via a two-phase transfer learning strategy on labeled MRI data. A custom classification head converts the backbone's rich feature embeddings into per-class probability scores. The entire inference pipeline — from raw image upload to annotated heatmap output — runs within a Flask web application deployed on Hugging Face Spaces.

CLASS 01
🔴 Glioma
Malignant tumors arising from glial cells. Characterised by irregular, heterogeneous enhancement and surrounding oedema. Most common primary brain malignancy and the most morphologically variable class.
CLASS 02
🟡 Meningioma
Typically benign, slow-growing tumors originating from the meninges. Present as well-circumscribed extra-axial masses with homogeneous enhancement — visually distinct from intra-axial lesions.
CLASS 03
🔵 Pituitary Tumor
Adenomas of the pituitary gland in the sella turcica. Highly distinctive location and enhancement pattern make this the model's best-classified category, achieving 0.99 F1-score.
CLASS 04
🟢 No Tumor — The Critical Negative
Healthy brain tissue with no detectable pathology. Precision in negative classification is as clinically important as positive detection — false positives cause unnecessary invasive procedures, patient anxiety, and resource expenditure. The model achieves 1.00 recall on this class: every healthy scan is correctly identified.

PREPROCESSING DETAIL
Image Normalization Pipeline
Each uploaded MRI is resized to 224 × 224 using PIL, converted to RGB (ensuring grayscale MRIs with 1 or 4 channels are correctly handled), then passed through efficientnet.preprocess_input() which applies EfficientNet-specific normalization — pixel values rescaled to [0,1] and then normalised by the ImageNet channel statistics. This is critical: using a different normalization scheme than the pretraining normalization degrades feature quality significantly.
DATA AUGMENTATION
Generalization Strategy
To combat overfitting on the relatively small MRI dataset, four augmentation strategies were applied during training: Brightness enhancement simulates scanner exposure variation; Contrast enhancement mimics sequence parameter differences; Sharpness enhancement addresses image quality variation across acquisition sites; Random augmentation ensures the model never memorises exact training samples and generalises across scanner hardware.
03 — TRANSFER LEARNING

Why EfficientNetB0 over VGG16

Transfer learning is the practice of taking a neural network pre-trained on a large, general-purpose dataset and repurposing its learned representations for a new, related task. Instead of randomly initialising all weights and training from scratch on a few thousand MRI scans — which would lead to severe overfitting — we initialise EfficientNetB0's backbone with weights learned from 1.2 million ImageNet images across 1,000 categories.

The rationale is grounded in a fundamental property of CNNs: early layers learn universal, task-agnostic features — edges, gradients, textures, colour blobs — that are equally useful for classifying photographs of dogs or MRI scans of tumors. Only the deeper, more task-specific layers need to be adapted to the medical domain. This dramatically reduces the amount of labeled medical data required and the computational cost of training.

EFFICIENCY
Compound Scaling
EfficientNet's key innovation is compound scaling — simultaneously scaling network depth, width, and resolution using a fixed coefficient. This produces dramatically better accuracy-per-parameter than VGG16's brute-force depth scaling, achieving superior feature richness with 96% fewer parameters.
FEATURE REUSE
ImageNet Representations
ImageNet pre-training gives the backbone detectors for edges, textures, shapes, and object parts that transfer directly to MRI interpretation. Tumors exhibit characteristic textures, boundary gradients, and spatial patterns that these detectors respond to, giving the model a strong initialisation that training from scratch on ~3,000 MRI scans could never achieve.
DEPLOYMENT
Production Viability
At 5.3M parameters and ~20MB serialized size, EfficientNetB0 is uniquely suited for Hugging Face Spaces deployment — low memory footprint, fast cold-start, and CPU-viable inference. VGG16's 138M parameters would require dedicated GPU instances and significantly higher hosting costs.
04 — MODEL ARCHITECTURE

Backbone + Classification Head

The final model is a two-part composition: a frozen (or partially unfrozen) EfficientNetB0 backbone that acts as a universal feature extractor, and a custom classification head trained specifically on the MRI classification task. The head connects to the backbone via Global Average Pooling, which compresses the spatial feature maps into a compact 1280-dimensional embedding vector before the dense layers.

DESIGN CHOICE
Why GlobalAveragePooling over Flatten?
Flattening (7×7×1280) produces a 62,720-dimensional vector before the dense layer, creating 16M+ parameters in that one connection alone — massively increasing overfitting risk. GlobalAveragePooling2D reduces this to 1,280 parameters per neuron, providing built-in spatial regularisation and dramatically reducing the head's parameter count while preserving the most informative channel-level information from the backbone.
DESIGN CHOICE
BatchNorm + Dropout Together
BatchNormalization normalises the Dense(256) output, ensuring well-conditioned activations flow into Dropout. This combination is particularly effective when fine-tuning a large pretrained backbone with a small classification dataset — BN stabilizes the gradient scale difference between the frozen backbone and the newly initialised dense layers, while Dropout prevents memorization of the small training set.
05 — TRAINING STRATEGY

Two-Phase Transfer Learning

Training proceeded in two carefully sequenced phases designed to avoid the principal failure modes of transfer learning: feature distortion (updating backbone weights before the head is stable causes destructive interference with ImageNet representations) and underfitting (keeping the entire backbone frozen prevents the model adapting to medical imaging characteristics).

🧊
PHASE 1 — FEATURE LOCK
Backbone Frozen — Head Training Only
All EfficientNetB0 layers are set to trainable=False. Only the four custom head layers (GAP → Dense → BN → Dropout → Dense) are trained. This forces the head to learn to correctly interpret the backbone's frozen ImageNet features in the context of brain tumor classification. Running with frozen BN layers in the backbone is critical — unfreezing them with small medical datasets corrupts the learned normalization statistics. The Adam optimizer at lr=1e-4 trains only the ~330K head parameters.
Backbone: Frozen Head: Trainable lr = 1e-4 Loss: Sparse Cat. CE
🔓
PHASE 2 — FINE-TUNING
Last Backbone Layers Unfrozen
Once the classification head has converged and is producing stable gradients, the final MBConv blocks of EfficientNetB0 are unfrozen. These top layers learn high-level, domain-specific features — the model adapts its understanding of textures and morphological patterns specifically toward MRI characteristics. The learning rate is kept low (1e-4 or reduced via callback) to perform gentle weight nudges rather than destructive large updates that would erase the ImageNet representations in the shallower layers.
Last Blocks: Unfrozen Low LR: gentle updates Head: Continues training
📉
CALLBACK — ADAPTIVE LR
ReduceLROnPlateau
The ReduceLROnPlateau callback monitors validation loss and reduces the learning rate by a factor when no improvement is detected over a specified number of epochs (patience). This adaptive schedule prevents the optimizer from overshooting flat loss surfaces and allows fine convergence near the optimum — critical in fine-tuning where updates must be precise enough to improve task performance without corrupting backbone representations.
Monitor: val_loss Mode: auto Factor: 0.2–0.5 Min LR applied

REGULARIZATION
Augmentation Strategy
Four PIL-based augmentations applied stochastically during training: Brightness (simulates scanner exposure differences across institutions); Contrast (models sequence parameter variation in T1/T2 weighted scans); Sharpness (handles resolution variation between 1.5T and 3T MRI scanners); Random augmentation (combines the above stochastically to ensure no two epochs see identical training inputs, preventing memorisation).

07 — EXPLAINABLE AI

EigenCAM Activation Heatmaps

Explainability is not a feature in NeuroScan AI — it is a clinical necessity. A model that returns "Glioma: 92.4%" with no justification is clinically unusable: radiologists cannot trust, audit, or act on a black-box prediction. EigenCAM produces a visual saliency map that answers a critical question: which specific regions of this MRI scan drove this prediction?

Deploying AI in healthcare without explainability violates the principle of clinical transparency and is increasingly a regulatory requirement. The heatmap provides radiologists with an AI-generated second opinion that they can immediately cross-reference against their own anatomical knowledge — if the model highlights the correct region, confidence in the prediction is warranted; if it highlights background noise, the prediction should be questioned.

🔭
How EigenCAM Works
Gradient-free saliency via SVD on convolutional feature maps

EigenCAM is a gradient-free Class Activation Mapping method that operates entirely on the spatial feature maps of the last convolutional layer — no backward pass or gradient computation is required. This makes it significantly faster than Grad-CAM and avoids instability issues from vanishing gradients in deep networks like EfficientNetB0.


The algorithm extracts the feature map tensor from the final Conv2D layer (identified automatically by scanning the model layer stack in reverse). This tensor has shape (H, W, C) where H×W is the spatial resolution and C is the number of channels. The tensor is reshaped to (H×W, C) and mean-centred across the spatial dimension to remove channel biases.


Singular Value Decomposition (SVD) is then applied to the reshaped matrix: U, S, Vt = np.linalg.svd(reshaped). The first right singular vector Vt[0] captures the direction of maximum variance across the feature channels — it is the principal component of the activation space. Projecting the feature maps onto this direction via matrix multiplication reshaped @ Vt[0] produces a scalar importance weight for each spatial location.


The resulting (H, W) heatmap is ReLU-clipped (negative values removed — they indicate suppression, not activation), normalised to [0,1], resized to the input image dimensions via cv2.resize, and mapped to a Jet colourmap. The coloured heatmap is blended over the original MRI at 40% opacity using cv2.addWeighted, producing a clinically interpretable overlay that highlights the tumor-discriminating regions in red/yellow and suppresses background areas in blue.

INTERPRETABILITY
Clinical Transparency
The heatmap allows radiologists to instantly verify that the model's attention aligns with known tumor anatomy. A Pituitary prediction that highlights the sella turcica region confirms correct reasoning. A Glioma prediction that ignores the tumor mass signals a failure mode requiring expert override.
ADVANTAGE OVER GRAD-CAM
Gradient-Free Stability
Grad-CAM requires computing class-specific gradients, which can be numerically unstable in EfficientNetB0's Swish-activated MBConv blocks. EigenCAM's SVD-based approach is class-agnostic and always stable — it visualises the dominant activation pattern regardless of the predicted class, making it reliable across all four tumor types without per-class gradient computation overhead.
LIVE DEPLOYMENT
Real-Time Flask Integration
Heatmap generation runs automatically after every prediction in the Flask application. The overlay PNG is base64-encoded and returned in the same JSON response as the classification result, ensuring zero additional network round-trips. The entire pipeline — inference + EigenCAM — completes in under 2 seconds on CPU inference.
